CURABOT+ INTEGRATED DEMO PACKAGE WITH HC-SR04 OBSTACLE GUARD
============================================================

FILES
-----
CuraBot_ESP32_Integrated.ino  ESP32 firmware: encoder navigation + HC-SR04 obstacle detection + Wi-Fi HTTP API
server.js                     Node/Express proxy: forwards commands and status including obstacle fields
index.html / style.css        Dashboard with real-time Obstacle Guard monitor & emergency stop
script.js                     Dashboard logic: 1000ms polling, live obstacle distance, state transitions
package.json / package-lock   Node dependencies
.env.example                  Environment variable template (do not commit real .env)

HC-SR04 OBSTACLE GUARD SPECIFICATION
------------------------------------
- Sensor Pins:
    TRIG -> GPIO 4
    ECHO -> GPIO 35 (via existing resistor voltage divider)
- Obstacle Thresholds (Hysteresis):
    Distance <= 20 cm: Obstacle detected, automatically pauses both motors.
    Distance 20-25 cm: Remains paused if already in obstacle state.
    Distance >= 25 cm: Requires 3 consecutive clear readings before automatic resumption.
- Scope:
    Ultrasonic checks run during forward straight-line navigation.
    Encoder counts are preserved while paused; the robot resumes its interrupted segment.
    Wait time is excluded from movement timeouts.

IMPORTANT ROUTE ASSUMPTION
-------------------------
Provisional demo routes (straight segment = 40 cm):
  Ward A:          Forward
  Ward B:          Forward, Right 90, Forward
  Pharmacy:        Forward, Right 90, Forward, Right 90, Forward
  Emergency Room:  Forward, Left 90, Forward

The return route is generated by reversing the stored action list and inverting
its actions (forward <-> backward, right <-> left).

BEFORE UPLOADING
----------------
1. Open CuraBot_ESP32_Integrated.ino in Arduino IDE.
2. Select the correct ESP32 board and port.
3. Verify Wi-Fi SSID and PASSWORD near the top of the sketch.
4. Confirm motor & sensor wiring:
     LEFT encoder  A/B -> GPIO 18/19
     RIGHT encoder A/B -> GPIO 32/33
     TRIG -> GPIO 4, ECHO -> GPIO 35
5. Keep a physical battery disconnect accessible.

FIRST TEST - DO NOT SKIP
------------------------
1. Lift the robot so both wheels are clear of the floor.
2. Upload the firmware and open Serial Monitor at 115200 baud.
3. Wait for the ESP32 IP address to print.
4. Set ESP32_URL in your local .env to that IP, e.g. http://<ESP32_IP>.
5. In the backend folder, run `npm start`.
6. Open frontend/index.html in a browser.
7. Verify GET /status via the dashboard and confirm "ESP32 Online" and "Path Clear".
8. Wave your hand within 20 cm of the sensor while a route is active (wheels lifted)
   to verify that motors pause, the dashboard shows "OBSTACLE DETECTED", and
   motors resume when your hand is moved away (>25 cm).
9. Test emergency STOP at any time.

BACKEND
-------
The Node backend runs at http://localhost:3000. Its ESP32_URL must point to the
current IP printed by the ESP32. The laptop and ESP32 must be on the same LAN.

SAFETY NOTES
------------
- Dashboard STOP is a software stop. Keep a physical battery switch accessible.
- Keep wheels lifted for initial tests.
